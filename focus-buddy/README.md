# 专注伙伴 Focus Buddy

一个长在电脑上的「陪学小屋」：摄像头盯着你有没有认真学，一只像素风猫头鹰坐在课桌中间陪你，**任何时候都能被拎起来拖走**——拖到餐桌会吃面包、拖到书柜会找书、拖到床上会盖毯子睡觉。左侧墙上挂着一卷**今日计划卷轴**，写着你今天要做的事，点它就翻到计划页。玩手机时不会立刻吼你，而是等 1.4 秒再按四档递进、一档比一档硬地提醒你。休息时它会自己下桌，在整条地板上溜达，也会自己跑去床上睡一觉、到餐桌吃口面包、去书柜翻两页，睡醒接着走。

- 纯前端，无需安装，双击 `start.bat` 即可
- 摄像头画面只在本机浏览器里跑，不上传、不保存
- 识别模型全部在本地 `assets/`，断网可用

## 打开方式

双击 `start.bat`：会用 **Edge/Chrome 的应用窗口**（没有地址栏，像个软件）打开，窗口约 1400×880。

也可以自己起服务：

```bash
cd focus-buddy
python serve.py 8848
# 浏览器访问 http://127.0.0.1:8848/index.html
```

> 必须用 http 打开，`file://` 会因为安全限制拿不到摄像头、也加载不了模块。
> 也**别用 `python -m http.server`**：它把 `.mjs` 当 `text/plain` 发，ONNX Runtime 的加载器会被浏览器拒绝执行，YOLO 检测就不可用了。`serve.py` 就是为此写的，只多一条 MIME 映射。

### 休息测试版（独立 HTML）
想专门验收休息态（自由走动 / 睡觉 / 吃饭 / 翻书），用独立测试版，和正式版完全分开：
- 双击 `start-rest-test.bat`：在 **8849** 端口起服务，用应用窗口打开 `rest-test.html`（1500×900，右侧带控制面板）；正式版仍是 `start.bat` / 8848，互不占用。
- 也可以直接访问测试服 `http://127.0.0.1:8127/rest-test.html`。
- 页面顶部有橙色「🛋 休息测试版」横幅，一眼和正式版区分；**不改动** `index.html` 的任何行为。
- 打开即进休息态；右侧面板可调休息时长（30 秒 / 1 / 3 / 5 分钟）、重新开始、手动结束回学习态；倒计时归零会自动切回学习并提醒。
- 面板里还能选用云扬 / 云夏 / 云希三套离线音色并试听；点「加速演示」（`?walk=1`）可加快走动与犯困，方便快速看完全过程。
- 注意：`rest-test.html` 用了 ES module，**必须经 http 打开**；直接双击 HTML（`file://`）浏览器会拦截模块加载，用上面的 bat 即可。

### 发给朋友测试（Windows exe）

不想让朋友装 Python 或敲命令？发单文件即可：

- **正式版**：`交付包/专注伙伴.exe`（约 67 MB）——完整的陪学软件（小屋 / 计划 / 学习节奏 / 监督），**双击就运行**。
- **休息测试版**：`交付包/休息测试版.exe`（约 67 MB）——打开即休息态，右侧带休息倒计时控制面板，专门给朋友快速看猫头鹰走动 / 睡觉 / 吃饭 / 翻书。两个 exe 可同时打开、互不干扰。
- 它们都会自动挑一个空闲端口起本地服务，再用 Edge / Chrome 的「应用窗口」打开；朋友电脑上**不用装 Python**。
- 首次启动稍等几秒（exe 自解压 + 模型加载）；正式版弹出画面后允许摄像头权限，**休息测试版不接摄像头、不用授权**。
- 模型 / 配音 / 精灵全部内嵌，**运行时不联网**；「视觉大模型复核」默认关闭，主动打开才会上传裁剪帧。
- 关掉应用窗口后后台可能还留着服务，任务管理器结束「专注伙伴」或「休息测试版」进程即可完全退出。
- 若 Windows Defender 拦截（PyInstaller 打包偶尔被误报），选「更多信息 → 仍要运行」。

## 界面里有什么

**左边是一列按钮，点了就整页切过去**（不做上下滚动的长页面）：

| 按钮 | 打开什么 |
| --- | --- |
| 🦉 小屋 | **默认主界面**＝像素风房间：现成的无遮挡版背景（矮床 / 矮书柜 / 餐桌都画在背景里）、**墙上的今日计划卷轴**、课桌上的**小木鱼**、拱窗、猫头鹰；画面内**只显示右上角一个昼夜切换按钮**；休息时猫头鹰自由走动 |
| 📋 今日计划 | 一整块木质**夹板**，中间压着一张横线纸，计划用手写体「写」在格线上；勾完成、删除、点一条设为「正在做」 |
| ⏱ 学习节奏 | 学习 15/25/45/60 分 × 休息 5/10/15 分、大倒计时、背景音（雨 / 鸟鸣 / 树叶 / 虫鸣） |
| 📷 监督 | 大画面摄像头、人脸 / 视线 / 手机三个灯、校准、演示 |

主界面刻意留白：状态徽标、阶段、倒计时圆环、底部任务 / 统计条、「自动」按钮都**不显示**（DOM 仍保留，计时与监督逻辑照常写入，一行都没改）。要看专注时长 / 提醒次数，去左侧栏统计或「学习节奏」页。顶部标题栏（开始学习 / 暂停 / 设置）和左侧按钮导航保留。按钮上的橙色小数字 = 还剩几条计划没做。

- 想临时看回完整 HUD：地址加 `?hud=1`；想看家具热区叠图：加 `?furn=1`。
- **测试服**：地址加 `?test=1`，右上角会多出一个「🛋 进入休息」按钮，点一下立刻进休息态看猫头鹰自由走动，再点变「📖 回到学习」切回来。`?rest=1` / `?walk=1` / `?debug=1` 也会自动带上它。这个按钮**只在测试参数下出现**，正式访问依然只有一个昼夜按钮；它只切场景状态机，不动计时与检测。
- 角色说话的临时台词气泡仍保留（约 3 秒自动消失），它是提醒反馈、不是常驻控件。**有字幕就有声音**：所有气泡（含第 1/2 档警告、学习态拖拽警告、轻点互动、休息态自言自语）都会用设置里选的语音朗读出来。

## 猫头鹰怎么陪你

**只有一个角色，就是这只暖棕色猫头鹰**；旧版的小猫 / 小猪 / 小春 / 小阳已全部移除。
素材按 v3/v4 + v7/v8 交付包：书桌上的全部精灵都是**正面朝观众**，换贴图时不移动、不翻转、不改大小；
v7 起睡觉 / 吃饭精灵改成**不带床架、不带椅子**的版本，需要贴合叠到背景里已有的家具上。

- **随时可拖**：STUDY / ALERT / PRAISE / REST 四种状态都能按住拖走（只有校准、启动那一瞬间暂时禁拖）。
  拖动中换成 `owl_flying` 正视图展翅精灵，家具热区会亮起虚线框；松手落到家具上用**贴合落点**，落在空地则回地面（脚底 y = 0.645h），x 停在你放下的位置。
- **轻点一下**：说句话，位置和动作都不变。
- **拖到或点击三件家具**（v7/v8「无家具版」精灵，全部正面）：

  | 家具 | 动作 | 精灵 | 贴合落点 (x, y) |
  | --- | --- | --- | --- |
  | 餐桌 | 悬空坐姿啃面包，坐在背景自带的右椅上 | `owl_eating_bread.png`（628×849） | (0.905, 0.755) |
  | 书柜 | 踮脚够书 | `owl_finding_book.png` | (0.785, 0.765) |
  | 床 | 上半身盖红被，叠在背景床的红毯上 | `owl_sleeping.png`（802×909） | (0.190, 0.679) |

  精灵本身**没有床架 / 枕头 / 椅子**，所以不会再出现「床摞床、椅摞椅」；落点由 `js/pixel-scene.js`
  顶部的 `FIT_SPOT` 统一配置，连拖拽松手的位置也会对齐到贴合点。离开家具再松手，就回到当前状态本来的动作。
- **昼夜**：同一张 1536×1024 无遮挡背景叠成两层、同坐标，夜层只加冷色压暗滤镜，用 0.5 秒 alpha 交叉淡化，家具与窗户位置零跳动。
  按系统时间自动（7:00–18:00 白天），右上角唯一的按钮可手动切；**右键**该按钮恢复按时间自动（「自动」按钮不再显示）。
- **墙上的卷轴**：左侧墙面挂着像素风计划卷轴，写前 4 条计划（`✓` 已完成 / `□` 待办，正在做的一条加粗），
  底部显示「还有 N 条 · 已完成 X / Y」。新增、删除、勾选计划后自动刷新；点卷轴或按回车直接跳到「今日计划」。
- **休息态自由走动（v6 / v10 四相位方向帧 / v11 自主行动）**：进入 REST 先从课桌下到前排地板，然后一直循环：
  `owl_idle` 站立张望 0.8~2.6 秒 → 决定这一趟去哪 —— **45% 去家具做点事**（床 / 餐桌 / 书柜三选一，不连着去同一处），
  其余在地板上随机走位 → 按方向选 `owl_walk_left_1~4`（朝左）或 `owl_walk_right_1~4`（朝右），
  按 1→2→3→4 顺序各约 110ms 循环走过去 → 走到家具前站定后小跳上去（460ms，带一点弧度），
  换 `owl_sleeping` / `owl_eating_bread` / `owl_finding_book` 待 6~45 秒（睡觉最长），**到点自己起来接着溜达**。
  **左右朝向由素材自带的专属帧表达，运行时不做任何镜像 / 翻转**。
  四相位素材高度本身不同（并拢帧最高、交错帧最低），运行时按 `0.30h × 自然高 / 1003` 换算显示高、
  脚底对齐，于是走路有自然的身体起伏；起伏上限由 `WALK.bobMax`（默认 3.5%）兜住，避免个别画小的帧在循环里跳大小。
  地板横向范围放到 `0.08~0.92`（几乎整条地板，不再只围着书桌），走动速度 115 px/秒（原 75），
  帧间隔相应加快到 110ms，步速快但脚下不打滑。参数都在 `js/pixel-scene.js` 顶部的 `WALK` / `OUTING` 里。
- **犯困上床**：REST 里连着 30 秒没换过动作、或点一下床 → 切 `owl_sleepy_walk`（揉眼拖小毯子）慢慢挪到床边
  → 到达切 `owl_sleeping` 躺下（直接落在床毯贴合点，不会跳位），睡 20~45 秒后自己醒来继续溜达。
  走动中随时可以拖拽（拖拽时切 `owl_flying`），也能被切回 STUDY 立即打断；拖到空地松手会继续散步，点 / 拖到床则去睡觉。
- **状态**：STUDY `owl_reading` → ALERT 四档 `owl_alert_notice` / `owl_alert` / `owl_alert_lean` / `owl_alert_stand` → PRAISE `owl_break_mug` → REST `owl_break_mug`。
  所有 PNG 用 `image-rendering: pixelated`（最近邻），角色按整数像素落位、不用 `transform`，边缘不会糊。

角色锚点恒为 x = 0.5w、脚底 y = 0.645h、高 = **0.30h**（v2 起从 0.235h 放大）；换精灵只换 `src`，不搬坐标。

## 走神了会怎样

摄像头判定走神，**默认只有两件事会真的敲木鱼**：**手机在手上**、**人离开座位**。
低头 / 转头 / 抬头 / 闭眼只当作辅助信息（状态栏会显示「低头中（不提醒）」）——因为低头看书、低头写字和低头玩手机在画面上几乎一样，光看脸正不正判断不了，用它当判据必然误报。
如果确实想要更严格，在设置里打开「低头 / 转头也算走神」即可恢复旧行为。

**玩手机**单独走四档递进（v3 规格），成立 **1.4 秒**后才出声，给「只是拿水杯」留退路；音量逐档渐强，角色固定在课桌中央，只换贴图。**每一档的台词都会朗读出来**（音色在设置里选）：

| 档 | 时间 | 精灵 | 声音 |
| --- | --- | --- | --- |
| 1 察觉 | +1.4s | `owl_alert_notice` 一翅抬到胸口 | 单音木块 0.25s（0.06）+ 朗读「盯——手机拿起来了」 |
| 2 轻提醒 | +4.4s | `owl_alert` 双翅叉腰 | 两音下行木琴 0.6s（0.13）+ 朗读「手机放下，现在就放。」 |
| 3 认真警告 | +12.4s | `owl_alert_lean` 前倾凝视 | 三音木琴 0.9s + 朗读台词（0.20） |
| 4 最后通牒 | +20.4s | `owl_alert_stand` 站起抱胸 | 稍强三音 + 朗读升级台词（0.27） |

**文案语气（v11 改硬）**：不再用商量的口吻，改成短句、直接下指令，但不骂人、不吼。例如第 3 档
「手机放下。这一章还没看完呢。」「别装没看见我，手机放桌上。」，第 4 档
「最后一次：放下手机，不然这一轮白算了。」「再拿一次我就不提醒了，直接记你走神。」
第 1 档只给一句「（盯——手机拿起来了）」，第 2 档「手机放下，现在就放。」；手机放下后仍会说「好，我们继续这一章」收尾。
台词池在 `js/pixel-scene.js` 的 `ALERT_LINES` / `FINAL_LINES`，想换口吻直接改这两组。

**配音是全局的**：朗读统一挂在 `showLine()`，所以不只四档提醒——轻点互动、拖拽警告、休息态自言自语，以及「学习 25 分钟，记住了」这类设置反馈气泡，只要有字就有声；新字幕会顶掉上一句。圆括号里的动作描写（如「（盯——手机拿起来了）」）朗读时只去掉括号符号、内容照念。唯一例外是设置 →「提醒方式」里主动选了「只看字（静音）」——那是你自己要安静；默认「气泡+语音」全部会读。

### 三套离线配音（默认云扬）
固定台词不用浏览器合成，改用 **edge-tts（微软在线语音）预生成 MP3**：三套音色各 68 条，放在 `assets/voice/`，音质接近真人，**播放不联网**。

| 音色 | 特点 | 前缀 / 映射 |
| --- | --- | --- |
| 云扬（默认） | 专业沉稳男声 | `v_*.mp3` / `js/voice-map.js` |
| 云夏 | 可爱童声 | `xia_*.mp3` / `js/voice-map-xia.js` |
| 云希 | 阳光男声 | `xi_*.mp3` / `js/voice-map-xi.js` |

- `js/voice.js` 的 `speakText()` 按选中的音色取对应映射，命中就播本地 MP3；三份 map 都由生成脚本自动写出来，别手改。
- 没预录的句子（带数字的，如「学习 25 分钟，记住了」）回退到系统语音：云夏挑中文女声、云扬 / 云希挑中文男声兜底，不会突然变回系统默认女声。
- 「📷 监督」页的「提醒音色」卡片和设置 →「提醒语音」**两处都能换音色、实时同步**，选中就试听；默认云扬。选系统音色则全程走系统语音，选「只看字（静音）」则完全不读。
- 想加 / 换台词：编辑 `assets/voice/生成配音.py` 的 `LINES`，跑 `python assets/voice/生成配音.py --all` 重新生成三套（联网一次，之后离线可用）；缺的会自动补，真要覆盖已有文件加 `--force`。只生成单套用 `--voice yunxia` / `--voice yunxi`。
全部是正弦 / 三角的柔和木质音，没有警笛、蜂鸣；手机放下会取消尚未触发的档位。拖拽中不抢飞行精灵，松手后恢复当前档位。
其余走神原因是即时的一声轻木质提示音。**书桌上放了一只小木鱼**：只要被判定走神（含玩手机），木鱼就敲一下——木槌落下、鱼身压缩、头顶冒出「+n」提醒次数；玩手机这一路仍然静音（先敲画面、1.4 秒后才由四档提醒出声），不抢提醒节奏。也可以**自己点一下木鱼**玩，冒「咚」但不计入走神统计。木鱼是 SVG 硬边绘制（`index.html` 的 `#pxMuyu`），敲击动画与计数在 `pixel-scene.js` 的 `knock()`，由 `app.js` 的 `knockFish()` 触发；检测逻辑一行没动。

判定节奏（标准档）：玩手机 0.7 秒、离开座位 5.2 秒；打开「低头 / 转头也算走神」后另有低头 2.6 秒、转头 3.2 秒、抬头 3.6 秒、闭眼 6.2 秒。「宽松 / 标准 / 严格」三档在设置里调。

## 第一次用：10 秒校准

点「开始学习」→ 允许摄像头 → 走三步：坐正（2.6 秒）、低头（3 秒）、转头（2.6 秒）。
系统会算出你自己的低头 / 转头阈值，所以「低头 20°」是真的 20°。校准存在浏览器里，下次不用重做（设置里可重置）。

## 识别原理（想改代码的话）

| 信号 | 做法 |
| --- | --- |
| 人在不在 | MediaPipe Face Landmarker（478 关键点） |
| 头朝哪 | 用眼外角 / 额头 / 下巴四点构造面部坐标系，取**法向量**算 pitch/yaw |
| 有没有手机 | 三路并行取最高分：① COCO-SSD 整帧（约 0.4 秒一次，`detector.js`）② COCO 裁剪放大 ③ **开源 YOLO11n 多尺度（离线，主力）**；都判"手持"还是"平放" |

判定是「状态机 + 每类原因独立缓冲」，恢复要持续 1.6 秒才销案。休息阶段默认不监督（设置里可打开）。
**`js/detector.js` 与 `judge()` 的阈值 / 缓冲一直没动过**，像素小屋只挂接已有判定结果。

| 现象 | 处理 |
| --- | --- |
| 明明在学却老被提醒 | 先看设置里「低头 / 转头也算走神」是不是被打开了（默认关闭）；再调「宽松」档或重做校准 |
| 玩手机没反应 | 光线太暗 / 手机被手挡住 / 手机在画面外；把摄像头抬高、拉远，让**手和桌面**都进画面 |
| 低头看书被当成玩手机 | 不该发生了：低头本身不报警，只有「手机在手上」才报警；若平放手机仍报，调大 `PHONE.nearFaceK` 或 `scoreMin` |
| 转头被误判 | 默认已不判转头；若打开了姿态开关，改回关闭或用「宽松」档 |
| 没声音 | 浏览器要求先有一次点击才允许发声，点过「开始学习」就正常；再查系统静音 |
| 语音是女声 / 想换个声音 | 默认已是「云扬」离线男声 MP3。三套离线配音可直接选：云扬（沉稳男声）、云夏（可爱童声）、云希（阳光男声），各 68 条固定台词、播放不联网；带数字的句子回退系统语音（云夏挑女声、另两个挑男声兜底）。设置 →「提醒语音」或监督页「提醒音色」都能换，选中即记住、可点「试听」。还可换系统音色（列表来自 Windows 已装语音，「设置 → 时间和语言 → 语音 → 管理语音」可添加），Edge 还会多出在线自然人声，Chrome 只认本地语音。音调/语速（仅系统语音生效）在 `js/voice.js` 的 `DEFAULT_TONE`（pitch 0.92、rate 0.96） |
| 摄像头打不开 | 地址栏摄像头图标 → 允许；关掉占用摄像头的软件 |
| 窗口太大/太小 | 拖窗口边框即可，场景会等比缩放；1366×768 也放得下 |

### 手机判定细化（手持 / 平放 / 无，不动 detector.js）
`detector.js` 只输出「手机置信度 + 一个框」，`app.js` 的 `refinePhone()` 在调用侧再判一层：
- **手持才报警**：手机框靠近人脸框（水平偏差 < 脸宽×0.95，纵向在脸下方 1.1 倍脸高内）→ `handheld`
- **平放不报警**：远离人且在画面下 40%（`cyN > 0.60`）→ `on_desk`，监督页状态显示「手机在桌上」，框画成琥珀色
- **形状过滤**：宽高比不在 0.22~3.2 的框直接剔除（笔、画面边缘、书本、键盘误检）
- **多帧投票**：1.5s 窗口内至少 4 次命中且占比 ≥55% 才判定，单帧抖动不算
- **放下即退出**：连续 700ms 没有新命中就清空窗口，不会因为旧记录拖着不恢复
- 判定阈值：单独判定 `scoreMin 0.45`；协同判定 `scoreSoft 0.38`（等于 detector 内部最低返还分，再低就没有数据了）。
  要调灵敏度改 `PHONE` 常量：`scoreMin / scoreSoft / voteMin / voteRatio / softVoteMin / holdMs / deskBottom / nearFaceK / hoverK`

### 裁剪二次检测：解决「手机在画面里太小，模型认不出」
整帧 640×480 里，胸前的手机常常只占 3~5%，COCO-SSD lite 直接认不出。`cropPhoneDetect()` 在整帧漏检时
把画面中下部（`x 0.10~0.99 / y 0.26~1.00`）裁出来放大到 **512 短边**再检测一次，框再映射回整帧坐标，
交给 `refinePhone()` 同一套手持/平放规则处理——等于给手机加了 3~4 倍倍率。

- **只在需要时跑**：整帧已检出（≥0.45 且有框）就跳过，省算力
- **独立节流** 700ms，结果有效期 1600ms；画布复用，不新建 DOM
- **两路取更强**：整帧分 vs 裁剪分，取高的那路，`rt.phone.src` 记 `full` / `crop`，监督页读数后标「裁剪」
- **串行化**：同一个 coco 模型被两路调用，`serializeCoco()` 在运行时把 `detect` 串成队列，避免互相打断（`detector.js` 一行没改）
- 要调：`CROP` 常量 —— `x0/y0/x1/y1`（裁剪窗口）、`side`（画布短边）、`intervalMs`、`score`（裁剪判定阈值）、`validMs`

### AI 复核：本地分不清的，交给视觉大模型

本地 COCO-SSD 只能回答「画面里有没有像手机的东西」，分不清「拿在手里看」和「平放在桌上」，
更分不清「低头看书」和「低头看手机」。`js/vision-ai.js` 在**灰区**抽一帧上云，用固定 JSON 提示词
要一个结构化结论，再由 `app.js` 覆盖本地判断。

- **什么时候才会调用**：本地手机分 ≥ `0.30`、或本地已判「手机在桌上」；且本地还没确信手持。
  没有手机迹象时一次都不调用，积分不会白烧。
- **频率**：最小间隔 6s（`VISION.intervalMs`），一条结论有效期 7s（`holdMs`），有效期内不重复问。
- **结论如何生效**：`phone_distraction`（置信 ≥0.6）→ 直接判 `handheld` 并走原来四档提醒；
  `focus` → 撤销本地误判（手机平放就显示「手机在桌上」）；`unclear` → 不采信。
- **失败只降级**：断网、限流、鉴权失败都只是「本轮不复核」，本地检测与提醒照常工作。
- **隐私**：复核时会把**裁剪后的画面**（默认 768 宽 JPEG）上传到模型服务；不想上传就在设置里关掉。
- **模型**：自动从云服务目录里挑第一个支持图片的模型（优先 `fast-model`）。换模型改 `vision-ai.js` 的 `CFG.prefer`。
- **看在哪**：监督页「手机分」下面新增一行 **AI 复核**，会显示「手持看手机 · 0.95」「专注（手机平放）· 0.90」
  「就绪（fast-model）· 6 次」这些状态。

### 「手机分」读数：先看数，再判断是谁的问题

监督页的「实时状态」下面多了一行**手机分**，把检测器内部状态直接摊开：

| 显示 | 含义 | 该怎么办 |
| --- | --- | --- |
| `0.00 · 已关闭` | 设置里关掉了手机检测 | 设置 → 勾上「启用手机检测」 |
| `0.00 · 模型未就绪` | COCO-SSD 没加载成功（`detector.cocoReady === false`） | 刷新页面重开；看控制台 `[coco-ssd]` 报错 |
| `0.00 · 未检出` | 模型在跑，但画面里没有认出手机 | 手机太小 / 太暗 / 被手挡住 / 在画面外 |
| `0.3x · 太弱 · 忽略` | 认出了但分数太低，不作数 | 把手机挪到画面中间、别让手挡住屏幕 |
| `0.3x~0.4x · 疑似 · 待确认` | 认到了、票数还不够或在协同判定中 | 保持几秒不动就会升级成手持 |
| `0.5x · 手持 · 报警` | 判定成立 | 正常，会走四档提醒 |
| `0.xx · 在桌上 · 不报警` | 判定为平放在桌面 | 正常，不算分心 |

### 姿态降级：低头不再等于走神（更重要的一次修正）

原先 `judge()` 把「低头」当成独立判据（低头 2.6 秒就提醒），但低头看书、低头写字、低头玩手机在摄像头画面上几乎没差别，必然误报。现在改成**证据分级**：

| 证据 | 处理 | 会不会敲木鱼 |
| --- | --- | --- |
| 手机在手上（`handheld`） | 硬证据，走四档提醒 | **会** |
| 人不在画面里（`gone`） | 硬证据，5.2 秒宽限 | **会** |
| 低头 / 转头 / 抬头 / 闭眼 | 只存进 `rt.posture`，供协同判定与指示灯用 | **不会**（除非打开设置里的开关） |
| 低置信手机框（0.38~0.45）+ 贴近身体 + 正在低头/闭眼 | 协同证据，投票更严（6 次 / 占比 72%） | **会**，判 `phone` |

- 设置里新增开关「低头 / 转头也算走神」，默认关闭；打开即恢复旧的姿态判据（`settings.posture`）。
- 状态栏在关闭时也会显示「低头中（不提醒）」，让你知道检测在跑、只是不打断你。
- 低置信协同判定是为了补回「低头玩手机、但手机识别分不高」的情况：它要求**手机框贴近身体**与**低头/闭眼**同时成立，单独低头、单独低分框都不作数。

### 开源 YOLO11n 检测：换成更强的开源模型（这次是主力的提升）

原来的手机识别只有 `detector.js` 里的 **COCO-SSD lite**，输入 300×300。手机在整帧里只占几个百分点，缩到 300 基本被抹平，所以经常"看不到手机"。这次从 GitHub 上找了现成的开源模型接进来。

**用了什么**

| 项目 | 作用 | 许可 |
|---|---|---|
| [Ultralytics YOLO11n](https://github.com/ultralytics/ultralytics) 的 ONNX 导出 | 目标检测（COCO 80 类，我们只取 `cell phone` 和 `person`） | AGPL-3.0 |
| 权重来源 [alanminu/focus-guard](https://github.com/alanminu/focus-guard) `models/yolo11n.onnx` | 端侧手机检测，正是这个用法 | AGPL-3.0 |
| [onnxruntime-web](https://github.com/microsoft/onnxruntime) 1.20.1（WASM） | 在浏览器里跑 ONNX，纯本机推理 | MIT |

GitHub 直连被网络拦了，权重是经 `cdn.jsdelivr.net` 代理拿下来的，之后全部落在本地，**运行时完全不联网**。

**关键：多尺度两段检测**

实测两张对照图得到一条很明确的规律：

| 画面 | 整帧 320 检测 | 裁手部区域放大后 |
|---|---|---|
| 双手举手机低头看 | ❌ 认不出 | ✅ **0.78** |
| 低头写字、手机平放桌角 | ✅ **0.72** | ❌ 认不出（手机在人体框外） |

所以 `js/yolo-phone.js` 做两段：整帧先跑一次，若没有 ≥0.45 的手机，就按**人体框下半部**（没有人体框时用人脸下方）裁一块再跑一次，取更高分。两段各约 60ms，合计约 120ms。

**接进判定链的方式**

- `app.js` 的 `yoloTick()` 每 900ms 跑一次（异步，不阻塞主循环），结果存 `yolo.{score, box, at, stage}`
- `refinePhone()` 把它当第三路证据：整帧 COCO / COCO 裁剪 / YOLO 三路比分，取最高
- 有 YOLO 之后就不再跑 COCO 裁剪（`cropPhoneDetect` 直接返回），避免三路模型同时跑把画面拖卡
- 关掉设置里的「YOLO 增强检测（离线）」就退回原来的纯 COCO 逻辑

**模型输入是 320 不是 640**

这个 ONNX 是固定 shape 320 导出的（ORT Web 1.20 不暴露 inputMetadata）。`yolo-phone.js` 会先用期望尺寸空跑一次，从报错的 `Expected: 320` 里读出真实尺寸再校准，所以换成别的导出（比如 640）也不用改代码。

**必须用 `serve.py` 启动**

ORT 的 wasm 加载器是 ES module（`ort-wasm-simd-threaded.mjs`），而 `python -m http.server` 把 `.mjs` 当 `text/plain` 返回，浏览器会拒绝执行，报 `Failed to fetch dynamically imported module`。`serve.py` 只比标准服务器多做一件事：给 `.mjs` 正确的 `Content-Type`。`start.bat` 已经改成用它。

- 想调灵敏度：`app.js` 顶部 `YOLO` 常量 —— `intervalMs`（检测间隔）、`reseeBelow`（多低才再裁一次）、`conf`（采信阈值）
- 想换模型：`js/yolo-phone.js` 顶部 `YOLO_CFG.modelUrl`，换成你自己的 ONNX 即可（输入尺寸自动校准）
- 模型文件：`assets/models/yolo/yolo11n.onnx`（10.6MB）；运行时：`assets/vendor/ort/`
